# 部署说明

本页说明正式环境中的管理员认证配置、首次初始化和 JWT 升级。开发环境的启动方式见 [README](../README.md#快速开始)。

## 认证配置

通过机密配置向 API 提供 `Authentication__SigningPrivateKeyPem`。该值为至少 2048 位的 RSA 私钥 PEM，支持 PKCS#8 或 PKCS#1 格式。同一部署的所有 API 实例使用同一把持久化私钥。私钥禁止写入版本库或日志。

前端通过应用同源的 HTTPS `/api` 地址访问后端，以便浏览器发送刷新 Cookie。

## 首次部署

先对目标数据库应用 EF Core 迁移，再启动 API 和前端。打开应用的 HTTPS 地址，在「设置管理员密码」页设置并确认密码，然后使用 `admin` 登录。密码长度为 6–20 个字符，保留首尾空白。

初始化入口匿名开放。公网可达时，第一个成功设置密码的人将成为管理员，因此应用启动后应立即初始化。全新实例被抢先初始化且尚无业务数据时可重新部署。已有数据时可通过[重置管理员密码](#重置管理员密码)恢复，保留数据库和数据卷。

## 从 Cookie 认证升级到 JWT

1. 停止所有旧版 API 实例，确认旧 API 已停止访问目标数据库。
2. 应用新版 EF Core 迁移。迁移创建独立的 `RefreshTokens` 表并删除 `AdminSessions` 表，保留管理员密码、资料和最近登录时间。
3. 配置 JWT 签名私钥后启动新版 API 和前端。旧版登录全部失效，各设备须重新加载页面并使用原密码登录。

## 重置管理员密码

在 API 发布目录运行以下命令，向该进程提供目标数据库的 `ConnectionStrings__openerp`。

```bash
dotnet OpenERP.Api.dll reset-admin-password
```

命令仅连接目标数据库，更新已有管理员并撤销全部登录。未初始化的占位账户会在重置时完成初始化。签名私钥只用于 HTTP 服务，重置命令无需配置。交互模式隐藏输入并要求确认。自动化时追加 `--stdin`，由机密管理工具通过标准输入提供一行密码，避免把真实密码写进脚本或终端历史。失败时命令返回非零退出码。

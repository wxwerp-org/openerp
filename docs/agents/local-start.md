# 给 AI 助手的本机启动指南

收到“帮我把项目跑起来”，先检查当前工作区、原有实例和本机已装的软件。用户要继续看旧订单时，找回上次的实例、账号和数据目录。出现首次设置页面通常意味着打开了另一份数据。

## 第一次打开

两种方式都在这台电脑上运行，都由助手操作。第一次没有说明偏好，而且选择会影响安装内容时，用一句话介绍差别，再让用户选。下面是全新 Windows 电脑上的说法。

1. **在这台电脑上试用或改一改（推荐非技术用户）**。我会准备好运行项目需要的工具，你也可以随时让我改点东西。这条路无需为项目加装第二项里的两套软件。
2. **按团队的方式开发（推荐技术用户）**。我会帮你准备团队使用的开发环境，包括 Docker Desktop 和 WSL。即使一次都没打开 OpenERP，这两套软件装好后也会一直占用磁盘空间。

根据机器上的既有安装调整措辞。用户已经说“别装 Docker”或“按团队环境开发”时，直接照办。在 macOS 和 Linux 上只说明该系统实际需要的软件。在首次大量下载或安装前，检查目标盘剩余空间，说明会增加什么；可靠估算不到的体积不用报数。

## 执行

- **试用或修改源码**。本机已有可用且兼容的 Docker 引擎时可以复用，执行普通的 `aspire start --isolated`。用户明确要无 Docker、本机未安装引擎，或者远端引擎是唯一可用的引擎时，用 `aspire start --isolated --launch-profile native`。两条命令都在仓库根目录运行。原生入口能直接修改前端与后端代码。它和团队环境使用各自的数据。
- **按团队环境开发**。先检查本机引擎和已有工具；若缺少新的系统组件，说明实际影响后由用户决定。已安装但未启动或当前账户不能访问时，按实际原因处理。安装步骤见[环境准备](../development.md#环境准备)。
- **准备源码工具**。两种开发方式都使用仓库指定的 .NET SDK、Aspire CLI、Node.js 和 pnpm。优先复用已安装版本。Windows 有 WinGet 时，助手可以用 `winget install --id Microsoft.DotNet.SDK.10 --exact --silent` 安装缺少的 SDK，按系统提示确认权限。重新检查 PATH 和 `dotnet --list-sdks`。Aspire 按[仓库内的 Aspire 指引](../../.agents/skills/aspire/SKILL.md)准备。原生模式无需另装数据库或文件服务。

通过 Aspire 等待 API 与 Web 就绪，打开 Web 资源的 HTTPS 地址并验证登录页、首次设置页或已登录的应用。交付这个可点击的地址。首次管理员密码由用户在页面上设置。再次打开应用时使用原来的入口和数据目录。把代码改好后想留下来长期用，见[开发说明](../development.md#本机原生运行)。
